## Experiments proposed, not yet implemented or run

1. **First priority: separate acquisition from display delay.** Add or reuse
   identifier-free measurement of inventory reception, presence event processing,
   and kiosk render latency. To measure first acquisition physically, establish
   a reproducible placement/start marker; mock timing cannot establish RF capture.
   Compare fixed 5/10/15/20 cm positions, repeated approaches, one tag then all
   tools, and fixed orientation. Preserve operational state and data.
2. **Kiosk update experiment:** consider polling 1000→250 ms or an event-driven
   alternative, after measuring app response/load. Interval reduction alone can
   save up to about 750 ms of scheduling wait, not several seconds of missed RF
   reads. No poll change was made. If changed, update diagnostics' currently
   hardcoded kiosk_poll_seconds too; avoid mismatched reporting.
3. **Inventory mode A/B:** 01 versus 0F with one synthetic/agreed tag at the
   same positions. Measure first acquisition, read success rate, longest gaps,
   median/p95 round duration. Do not make 0F production default for many tools.
4. **ScanTime:** only consider a separately authorized bounded setting experiment
   if measurements reveal long/blocking rounds; existing ~50 ms rounds offer
   little evidence for improvement. Manual warns shorter limits can reduce reads.
   Preserve/read back settings and rollback only within explicit future approval.
5. **Frequency:** read-only inspection/vendor verification of existing band versus
   tag specification can precede any hypothesis. No blind channel/region tuning.
